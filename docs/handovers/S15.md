# S15 — Sort, filter and statistics

Status: complete
Date: 2026-11-20

## Delivered

- The Data tab repeats the desktop Sort & Filter group: a two-row A to Z / Z to A stack, a large Sort button, a large Filter toggle whose pressed state follows the caret's filter, and a Clear/Reapply stack that is disabled until a filter exists or has criteria. Home keeps the large Sort & Filter menu with Sort A to Z, Sort Z to A, Custom Sort..., a divider, Filter, Clear and Reapply; Clear and Reapply stay disabled without a filter. Artwork comes from `EditingGlyph.cs` and is drawn as vector glyphs. [Ribbon and menus](../../tests/e2e/data-sort-filter.spec.ts)
- The Sort dialog mirrors the desktop fields: Options..., My data has headers, Column, Sort On (Cell Values) and Order, with Sort by, the Sort column list from the selected range's header labels, and OK/Cancel. Sort Options holds Case sensitive and the Orientation group with Sort top to bottom. The Sort Warning offers Expand the selection or Continue with the current selection, shows "Sort range: ..." and uses Sort/Cancel, and a single-cell selection or a selection that already spans the region skips it. [Dialogs](../../tests/e2e/data-sort-filter.spec.ts)
- Header funnels appear only for a filter header row and for tables whose header row and Filter Button are on. The dropdown repeats the desktop layout: Sort A to Z, Sort Z to A, Clear Filter From "Header", Search, a tri-state (Select All), the distinct formatted values with checkboxes, and OK/Cancel. Search narrows the list, Select All applies to the shown values only, and selections survive a search round trip. Values from rows hidden by another column's criterion are not offered. [Checklist and search](../../tests/e2e/data-sort-filter.spec.ts)
- [data-commands](../../src/application/data-commands.ts) adds `sortData`, `setFilter`, `filteredRows`, `columnValues`, `recordSummary`, `currentRegion`, `filterRange`, `looksLikeHeader`, `compareSortKeys` and `localeTextOrder`. Sorting is stable per column type, keeps blanks last in both directions, relocates relative formulas with their styles and identities, moves whole records together under an active filter, and writes the sort indicator only when the sorted extent matches the filter. Merged cells, tables that are not fully selected and Python-bearing cells are refused. [Transactions](../../tests/integration/data-commands.test.ts)
- The Sort dialog starts from the sort already shown on the range: when the filter's sort arrow applies to the opened range, Column and Order open on that stored column and direction instead of the caret column and the menu's default. The Data tab Filter toggle follows the caret: a table's filter lights it only while the caret is inside that table, and it reads off outside. Pressing it while it reads off starts a filter for the selection: a selected area outside a table filters exactly that area, a single populated cell filters the data block around it, and a table's running filter is replaced because the sheet holds one. An empty selection reports "Select a range with data before turning on the filter."
- Filters are stored on the sheet with per-column allowed keys built from the shared formatter, so formatted values filter exactly as they display. Creating the filter from a cell uses the current region; a table filter is owned at the table's input extent and refuses to start while another range holds criteria. Clear keeps manually hidden rows hidden, and Off removes only the filter. Filtered rows leave the worksheet projection while manual hides stay independent. Selection statistics now exclude filtered rows, and SUBTOTAL follows the same criteria in the worker. Every sort, filter create, criteria apply, clear and column clear is one undo step. [Model](../../tests/integration/data-commands.test.ts) · [Grid projection](../../tests/e2e/data-sort-filter.spec.ts)
- F16 note, F17 and F18 are updated in [Feature-Parity](../Feature-Parity.md). No browser adaptation was needed: the desktop group, menus, dialogs and dropdown are reproduced, with DOM funnel buttons over the canvas header the same way table resize and total buttons are drawn.

## Remaining risks or blockers

- Sorting a range that contains Python cells is refused with "Sorting Python cells needs Python source rewriting, which is not available yet." S20 owns Python source rewriting; until then such ranges cannot be sorted.
- Filter keys are formatted display text, matching desktop `FilterKey`. Changing a number format while a filter is active can therefore change which records match; the desktop behaves the same way, and the dropdown lists the current values when reopened.
- The sort warning compares the selection with the current region, so a selection separated from its neighbors by a blank row or column sorts alone without a warning, as on the desktop.
- Reapply recomputes visibility from the stored criteria; it does not re-derive values from the sheet, matching the desktop's criteria-based reapply behavior.
- The desktop's Filter toggle is checked whenever the sheet has any filter. Here a table-owned filter only lights it inside that table, and pressing it elsewhere starts a range filter that replaces the table's, because the sheet holds one filter. This is the requested behavior and differs from `DataRibbon.UpdateFilterCommands`.
- The full browser suite is load-sensitive on this machine: different unrelated cases failed on each of two runs and all passed in focused runs. Their failures are recorded above rather than treated as passes.
