# S19 — XLSX exchange and loss reports

Status: complete
Date: 2026-11-22

## Delivered

- Implemented the desktop-supported XLSX subset in `src/persistence/xlsx`: bounded ZIP reading, relationship/content-type resolution, shared strings, scalar values, formula source with caches, the supported font/fill/border/number/alignment/gradient matrix, merges, row/column dimensions and visibility, freeze and 1900/1904 conversion.
- Import is wired to File → Open for `.xlsx`. It shows a deduplicated review report with Continue/Cancel; Continue adopts the workbook as a native browser-local project with `source: xlsx`, while Cancel keeps the current workbook. Unsupported formula text, array/shared-formula limitations and unverified caches are preserved instead of being replaced with zero.
- Export is a separate File → Export path with its own review report. It never evaluates formulas or Python, writes `calcMode="manual"`/`fullCalcOnLoad`, exports only materialized scalar Python caches, omits code/bindings/trust/tables/figures with a report, never invents a zero cache, and never clears the session's dirty state.
- Imported-XLSX provenance survives a native Save As for the session, so Export stays XLSX. When the File System Access picker exposes `isSameEntry`, Export refuses to overwrite the imported source; the input-file fallback cannot prove identity and is documented as a browser adaptation.
- Existing save paths were not changed: `workspace-store.ts`, the IndexedDB schema, local Save/Save As and native `.exlt` export are untouched. The only context addition to the save flows preserves XLSX export provenance and the imported source handle.
- Added `tests/unit/xlsx-styles.test.ts`, `tests/integration/xlsx-import.test.ts`, `tests/integration/xlsx-export.test.ts`, `tests/e2e/xlsx-files.spec.ts` and the `tests/desktop-xlsx` oracle. Import tests also round-trip every fixture through `saveNativePackage`/`loadNativePackage`, proving the browser-local adoption path works without changing the IndexedDB schema. Updated the persistence README, Architecture, Development and Feature-Parity (F01, F23, F24).

## Remaining risks or blockers

- Overwrite protection for the imported source depends on `FileSystemFileHandle.isSameEntry`; input-element imports (Firefox/Safari fallback) cannot verify identity before a selected export destination. The UI states the imported source must not be overwritten, but the browser cannot enforce it there.
- XLSX remains a reviewed subset, not full Excel round-tripping. Theme/indexed colors, rich text, AutoFilter/sort indicators, names/tables/charts/drawings/pivots/comments/validation/conditional formatting/hyperlinks/protection and hidden sheets are reported as losses. Unsupported formula source and caches are preserved but not evaluated.
- Rich text runs are flattened to their text (phonetic runs excluded); theme colors and unsupported fills are dropped with the `unsupported-color`/`unsupported-fill` reports.
- The desktop oracle requires external Release assemblies and is not part of CI; an unavailable assembly is a skip, not parity evidence.
- No new dependency, backend, schema bump or runtime change was introduced. No Git operations were performed.
