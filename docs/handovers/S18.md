# S18 — Browser file lifecycle and local recovery

Status: blocked
Date: 2026-11-21

## Delivered

- Implemented the browser-local New/Open/Save/Save As/Export/Close flow, Recent, replacement prompts, recovery snapshots, explicit reload recovery, tab-level workbook ownership, local preferences and v1-to-v2 migration.
- Added Quick Access Save before Undo and Redo, matching the C# toolbar order and 32px button size. It calls the same Save lifecycle as File backstage and supports the existing Ctrl+S shortcut.
- Clarified local versus disk persistence: first Save of an untitled workbook asks for its browser-local workbook name, and Recent has a confirmed Remove action that deletes the IndexedDB snapshot and recovery data only. A workbook must be closed first; another tab's active lease protects it. Disk and Downloads files remain untouched.
- Made the two native-package C# oracle tests conditional on the real Release assemblies being available. GitHub's Linux job now runs the portable package tests and reports those two checks skipped instead of trying to compile against an absent `C:/Temp/ExcelLight` checkout. Local runs with `DESKTOP_BIN` still execute the actual desktop comparisons.
- Aligned the new File backstage and Options UI to the C# source layout: the original command order, 200px navigation rail, 32px Home inset, a plain 32px Blank workbook command, 520px Options dialog, and 140px category rail with the source column gap. Kept the product dark-only and Python controls unavailable until their execution sprint.
- Added browser tests for layout, native open/save/export, local Save As, first-Save naming, Recent removal, imported provenance, unsaved choices, recovery, two-tab conflict/removal protection, transaction failure and valid/invalid migration. The WebKit multi-tab journey brings each page to the foreground before interaction, matching browser tab switching.
- Stored package payloads as `ArrayBuffer` in IndexedDB after WebKit rejected `Blob` records. The adapter restores `Blob` packages for the native reader and accepts both representations when reading existing records.
- Updated [Architecture](../Architecture.md), [Development](../Development.md) and [Feature-Parity](../Feature-Parity.md). No deployment contract or dependencies changed.

## Remaining risks or blockers

- The Definition of Done requires a clean production browser run. Firefox cannot launch in this Windows environment, the current Chromium suite has two failures outside S18, and the WebKit runner did not exit cleanly despite all scenarios reporting results. No browser engine result is being treated as proof for an engine that could not run.
- S18 functionality and its file workflow pass in Chromium and WebKit, including the desktop-derived GUI assertions, but S18 remains blocked until the required cross-browser verification completes cleanly. S19 must not begin on an unproven verification gate.
- No schema bump was needed: IndexedDB remains at v2 and reads legacy Blob records as well as byte-buffer records. No external service, network storage or runtime dependency was added.
