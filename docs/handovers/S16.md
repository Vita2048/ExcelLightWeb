# S16 — Find, view and navigation polish

Status: complete
Date: 2026-11-21

## Delivered

- Home → Editing gains the desktop's large Find & Select menu (Find... and Replace...), and Ctrl+F / Ctrl+H open the same dialog with Find/Replace tabs, replace-only fields, Within (Sheet/Workbook), Search (By Rows/By Columns), Look in (Formulas/Values), Match case, Match entire cell contents, a status line, and Replace All / Replace / Find All / Find Next / Close. Find opens on Values, remembers the last Find choice for the session, and only offers Values there; Replace keeps `Look in: Formulas` disabled, as on the desktop. Escape and Close dismiss without acting, focus returns to the grid, and Find Next is the primary action. [Dialog checks](../../tests/e2e/search-view.spec.ts)
- Find All fills the desktop results table (Book, Sheet, Name, Cell, Value, Formula) with per-sheet, per-row or per-column ordering and reveals a double-clicked match. Values searches the formatted display of every cell, including formula results; Formulas searches only cells that hold formulas, matching their stored source. Replace keeps the desktop's Formulas-only search over stored source so constants stay replaceable. Blanks never match, an empty query reports `Enter text to find.`, and Find Next wraps through the match list. [Transactions](../../tests/integration/search-commands.test.ts)
- Replace revalidates every target against the captured result (`Search result changed. Find again.` / `Search result is no longer available.`), keeps text cells as text, re-parses other values, does not wrap from the last match, and writes Replace All as one `Replace cells` undo transaction. Find and Replace keep independent 15-entry exact-deduplicated histories for the session; invalid or oversized values are ignored. [History and replacement](../../tests/integration/search-commands.test.ts)
- View → Zoom gains the large desktop Zoom dialog with 200/100/75/50/25% radios, Custom with a 10–400% number box, and Fit selection; the status and system-zoom controls share the same value. Fit selection sizes from the selection, visible headings and authored dimensions. Hidden rows and columns stay hidden at zoom. [Zoom checks](../../tests/e2e/search-view.spec.ts)
- View → Window exposes a large Freeze Panes flyout: Freeze Panes / Unfreeze Panes, Freeze Top Row and Freeze First Column, with the desktop status strings (`Froze panes.`, `Froze the top row.`, `Froze the first column.`, `Unfroze panes.`) and an unchanged-boundary notice. Boundaries are stored per sheet in authored state, pinned bands clip at zoom, the pinned edge paints the desktop's thicker divider over content and headings, and extreme viewport splits keep frozen bands hit-testable. [Freeze commands](../../src/application/view-commands.ts) · [Browser checks](../../tests/e2e/search-view.spec.ts)
- View → Show regains the Show Formulas checkbox beside Formula Bar, Gridlines and Headings; it shares its state with Formulas → Formula Auditing. Sheet navigation (Previous/Next, named tabs, New sheet) was already implemented and remains unchanged.
- [search-commands](../../src/application/search-commands.ts) and [view-commands](../../src/application/view-commands.ts) hold the search and freeze model with no React dependency. F19 is implemented and F20 is updated in [Feature-Parity](../Feature-Parity.md). No browser adaptation was introduced: dialog layout, options, ordering, statuses and ribbon groups follow `SearchDialog.cs`, `EverydayCommands.cs`, `DataRibbon.cs` and `FreezeChecks.cs`.

## Follow-up corrections

The first review of this sprint found four gaps, all fixed and covered by the updated tests above:

- The frozen edge drew no divider. `drawWorksheet` now paints the desktop `DrawFrozenDividers` rule: 2 CSS pixels times zoom (at least 1) in `#a0a0a0` (`--freeze-line`, `CanvasText` under forced colors) across the full canvas, over headings too, at each frozen row or column edge.
- Home → Editing had no Find & Select menu. The large menu with Find... and Replace... now matches `EditingRibbon.BuildEditingGroup` and the desktop magnifier and Replace artwork.
- Find defaulted to Formulas. It now starts on Values for the session, matching the requested workbook behavior; the last Find choice is remembered until the page reloads.
- The Options grid put Look in beside Within. It now follows `SearchDialog.cs`: Within and Match case on the first row, Search and Match entire cell contents on the second, and Look in on its own third row; the narrow layout stacks them in the desktop order.
- The Replace... menu item used the four-square `RibbonCommandGeometry` artwork. The Home menu now uses `EditingGlyph.Create`, the desktop's curved arrow icon, for Replace... and the desktop magnifier (handle at lower left) for Find & Select and Find....
- Formulas matched typed constants as well as formulas. Find now restricts Formulas to formula cells and their stored source; Values still searches every formatted display. The Replace tab deliberately keeps the desktop's stored-source search because it only offers Formulas and must keep replacing constants.

## Remaining risks or blockers

- Find and Replace histories live in application state for the session only. S18 owns the durable 15-entry histories required by the settings work.
- Freeze boundaries and zoom are view/workbook state that is not yet written to a file; S17 carries them through native packages.
- Search walks authored cells synchronously. Large workbooks are bounded by the existing 10,000-row × 100-column sheet limit, but no large-workbook timing benchmark was captured, so responsiveness on maximum-size sheets is unmeasured.
- Find's Formulas mode now excludes typed constants, a requested refinement that differs from the desktop's `EverydayCommands.Find`, which searches the stored source of every non-blank cell. Replace deliberately keeps that broader stored-source basis so the Formulas-only Replace tab can still replace constants.
- Values mode matches the shared formatted display, including cached formula results while a calculation is stale; the desktop does the same, but the stale state is visible only through the existing stale-cell indicator.
- The zoom dialog reproduces the desktop number-box clamping (out-of-range typing becomes 10 or 400) rather than rejecting input.
